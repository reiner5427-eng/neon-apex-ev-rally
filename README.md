# NEON APEX · EV Rally

HTML/CSS/JavaScript와 Three.js로 직접 만든 3D 전기차 레이싱 웹게임입니다. 기존 게임과 별도의 프로젝트입니다. 차량은 브랜드 공식 모델·에셋이 아닌 직접 제작한 스타일화된 메시입니다. 상표 소유자와 제휴 관계가 없습니다.

- 게임 실행: https://neon-apex-ev-rally.netlify.app
- 비공개 소스: https://github.com/reiner5427-eng/neon-apex-ev-rally

차체 곡면, 별도 유리와 필러, 금속 휠·브레이크·타이어, 차종별 램프와 반사 재질을 적용했습니다. 추적 카메라 기준 좌우 방향키도 수정했습니다. 운영 서버 연결과 두 브라우저의 참가·출발·기권 결과는 확인했으나, HTTP 지연으로 운영 3랩 완주는 아직 확정 검증하지 못했습니다. 자세한 검증 범위는 `VERIFICATION.md`에 기록합니다.

## 실행

Node.js 22 이상, pnpm 10.18.3을 사용합니다. `package.json`의 직접 의존성 버전을 고정하고 `pnpm-lock.yaml`을 포함합니다.

```sh
corepack enable
pnpm install --frozen-lockfile
pnpm dev
# http://localhost:8080
```

`index.html`이 진입점입니다. ES module과 HTTP API 때문에 파일을 직접 더블클릭하지 말고 HTTP 서버를 이용하세요. `pnpm build`는 로컬 Three.js 라이브러리를 포함한 `dist/`를 생성합니다. 외부 이미지나 CDN JavaScript 없이 실행됩니다. Google Fonts를 불러오지 못하면 시스템 폰트를 사용합니다.

```sh
pnpm test
pnpm build
```

## 경기와 차량

EV6, 사이버트럭, 모델 S, 모델 Y, 아이오닉 5, EV3의 실루엣·램프·차체 높이·길이·지붕 형태가 서로 다릅니다. 바퀴 회전과 앞바퀴 조향을 렌더링합니다. 성능과 충돌 판정 반경은 동일합니다. 혼자 경기는 선택 차량을 플레이어가 사용하고 다른 5종을 AI가 사용합니다.

Harbor Loop는 약 1.42km의 해안 트랙입니다. 12개 체크포인트를 순서대로 통과해야 한 랩이 인정됩니다. 3랩, 고정 1/60초 물리, 가드레일·차량 충돌, 부드러운 추적 카메라, 속도별 FOV, 실제 이동 방향과 차체 방향이 다른 드리프트, 타이어 자국·연기·부스터 불꽃을 제공합니다. AI도 같은 물리와 순서 검증을 사용하며 코너 감속·드리프트·부스터·아이템을 수행합니다.

아이템전에서는 7초 후 재생성되는 상자가 있습니다. 미사일은 앞선 상대에게 이동해 명중하면 1.7초 방해합니다. 물폭탄은 전방으로 1초 날아간 뒤 13m 반경에 2.2초 방해 효과를 줍니다. 바나나는 뒤에 설치되어 30초 동안 상대와 충돌하면 미끄러뜨립니다. 자석은 앞선 상대 방향으로 3.2초 가속합니다. 실드는 5초간 유지되고 공격 1회 차단 후 사라집니다. 한 번에 아이템 1개만 보유하며 타깃이 없으면 미사일·자석을 소비하지 않습니다.

전체 경기 제한 시간은 7분이며 첫 완주자 발생 35초 뒤 남은 차량은 DNF 처리합니다. 결과는 완주 시간순이고 미완주는 따로 표시합니다. 복귀 페널티는 해당 랩과 총 시간에 포함됩니다.

## 온라인: GitHub + Netlify만 사용

프런트엔드: Netlify 정적 호스팅. 서버: Netlify Functions. 공유 방 상태: Netlify Blobs의 site-scoped strong-consistency store. 별도 Render/유료 서버/외부 실시간 서비스/개인 API 키를 요구하지 않습니다.

### 동기화와 검증 수준

- 클라이언트는 약 180ms 간격 **+ 실제 요청 소요 시간**마다 HTTPS POST로 입력과 상태를 교환합니다. WebSocket 서버를 Netlify에 설치하는 방식이 아닙니다. 서버는 요청 사이의 시간을 60Hz 단계로 시뮬레이션합니다. 실제 상태 갱신 빈도는 연결 지연에 따라 낮아집니다.
- 주행 좌표, 속도, 게이지, 아이템, 체크포인트, 랩 시간, 최종 결과는 서버의 `core.js`가 계산합니다. 클라이언트가 좌표·랩·완주 시간을 제출해도 사용하지 않습니다. 서버에서 생성한 출발 시간을 공유하고 차량 위치/각도를 화면에서 보간합니다.
- 방 키는 고유 6자리 숫자입니다. 각 참가자에게 서버가 256비트 임시 토큰을 발급합니다. 토큰은 브라우저 메모리에만 보관하고 저장소에는 SHA-256 해시만 저장합니다. 방 코드만 안다고 다른 참가자의 입력을 변경할 수 없습니다.
- 방 변경은 ETag를 읽은 뒤 `onlyIfMatch`로 조건부 저장합니다. 동시 요청이 충돌하면 최대 8회 다시 읽고 계산하며 여전히 충돌하면 클라이언트가 재시도합니다. 방 생성은 `onlyIfNew`를 사용합니다. 서버의 순차 상태가 양쪽 결과의 기준입니다.
- 서버는 입력 키를 허용 목록의 boolean으로만 정규화합니다. 순서 번호가 오래된 입력은 무시합니다. 2.2초간 새 입력이 없으면 입력을 놓고, 25초간 요청이 없으면 기권 처리합니다. 나가기는 즉시 기권, 새로고침·기기 연결 끊김은 heartbeat 만료 후 기권입니다. 온라인 메뉴를 열어도 서버 경기는 계속됩니다.
- 대기방의 방장이 나가면 남은 참가자가 방장이 됩니다. 빈 방은 닫은 뒤 삭제합니다. 접근 없는 방은 30분 만료되며 시간당 예약 함수가 오래된 방을 정리합니다. 코드는 방마다 분리됩니다.
- 온라인에 AI를 추가하지 않습니다. 온라인 결과는 `saveSoloRecord`에 전달하지 않으며 저장 함수에도 온라인·AI·DNF 차단 조건을 둡니다. 명예의 전당은 완주한 혼자 경기 플레이어의 가장 빠른 단일 랩 기준 모드/트랙별 상위 10개입니다. 기록은 현재 브라우저 localStorage에만 존재합니다.

**한계:** HTTP 폴링과 강한 일관성 저장은 지속 WebSocket보다 입력 지연이 큽니다. 저지연 경쟁용 서버가 아니라 소규모 친구 대전용입니다. 서버 권위로 시간·좌표 조작은 막지만 자동운전/봇, 계정 기반 인증, 포괄적인 부정행위 방지는 구현하지 않습니다. 드물게 서버가 10초 이상 중단되면 양쪽 DNF로 종료합니다. 방 정보는 배포 간 유지되지만 서버 코드 변경 중 경기는 재입장을 권장합니다. 네트워크 지연 중 미래 위치를 예측하는 클라이언트 롤백은 없습니다.

Netlify Functions 실행, Blobs 읽기·쓰기, 데이터 전송은 계정의 사용량을 소비합니다. 무료 요금제 무제한 서비스를 의미하지 않습니다. 특히 온라인은 매 갱신마다 서버 읽기·쓰기가 발생하므로 소규모 사용을 전제로 합니다.

### 로컬 온라인

`pnpm dev`의 `/api/race`는 같은 서버 엔진을 메모리 저장소로 실행합니다. 두 브라우저가 같은 URL에 접속하면 실제 연결됩니다. 컴퓨터와 휴대전화가 같은 Wi-Fi에 있으면 `http://컴퓨터의LAN-IP:8080`에 접속하세요. 로컬 메모리 방은 서버 재시작 시 사라집니다. `server/index.js`에는 추가로 WebSocket 진단 서버도 남아 있지만 실제 게임의 기본 연결은 HTTP API입니다.

Netlify 함수/Blobs를 직접 에뮬레이션하려면 `pnpm exec netlify dev`를 사용할 수 있습니다. 실제 Blobs 환경은 Netlify 배포에서 자동으로 연결됩니다. 정적 파일만 Netlify Drop에 업로드하면 온라인 서버는 배포되지 않습니다. **반드시 Git 연결 빌드 또는 Netlify CLI의 함수 포함 배포를 사용하세요.**

### 배포

1. 이 프로젝트만 새 GitHub 비공개 저장소에 업로드합니다. 기존 저장소는 변경하지 않습니다.
2. Netlify에서 새 프로젝트 → GitHub 저장소 가져오기 → 이 저장소 선택.
3. 빌드 명령 `pnpm build`, 게시 폴더 `dist`, 함수 폴더 기본값 `netlify/functions`. 저장소의 `netlify.toml`을 사용합니다. 직접 의존성과 잠금 파일을 함께 설치하세요.
4. 배포 후 `/.netlify/functions/race`가 존재해야 합니다. 게임은 자동으로 동일 사이트 함수에 접속하므로 비밀키나 온라인 서버 주소를 설정할 필요가 없습니다.
5. 새 Netlify 사이트 주소를 두 기기에 공유하고 아래 절차를 실행합니다.

CLI 방식은 기존 Netlify 로그인이 있는 경우 `pnpm exec netlify login`, **새 사이트를 생성한 뒤** `pnpm build`, `pnpm exec netlify deploy --prod --dir=dist --functions=netlify/functions`를 사용하세요. 새 사이트 ID를 로컬 `.netlify/state.json`에 보관하며 Git에 올리지 않습니다.

### 두 기기 테스트

1. 같은 Netlify 주소를 두 기기에서 열고 각각 다른 이름·차량으로 온라인 1:1에 진입합니다.
2. A가 방을 생성하고 코드 복사. B는 코드를 입력하여 참가합니다.
3. A가 경기 모드를 선택하고 두 기기 모두 준비합니다. A가 시작합니다.
4. 두 화면에 같은 출발·상대 차량·아이템·순위·랩·결과가 나타나는지 확인합니다.
5. 메뉴를 열어도 상대가 움직이는지, 나가면 상대의 기권 승리가 되는지 확인합니다.
6. 명예의 전당을 새로고침하여 온라인 기록이 추가되지 않았는지 확인합니다.
7. 다른 방을 생성하여 이전 방의 참가자·아이템이 섞이지 않는지 확인합니다.

## 검증

`tests/game.test.js`: 차량 6종 배정, AI의 스피드/아이템 3랩 완주, 드리프트/부스터, 프레임 묶음 독립성, 충돌, 복귀 페널티, 역주행·결승선 반복 방지, 아이템 5종과 지속시간·실드·상자 재생성, 저장 분리·상위 10개·동률, 멀티포인터 입력.

`tests/network.test.js`: 실제 WebSocket 진단 클라이언트로 방 생성·검증·정원·준비·동시 출발·방 분리·결과·재대결·방장 이전·연결 끊김.

`tests/http-rooms.test.js`: 운영 서버와 동일한 HTTP 방 엔진의 조건부 저장, 동시 참가 충돌, 임시 토큰 인증, 조작된 좌표/완주 시간 거부, 두 참가자 3랩의 서버 확정 결과, 방 분리·재대결·기권.

로컬 브라우저의 `?qa=1`은 눈에 보이는 테스트 패널로 자동 입력을 켤 수 있습니다. 혼자 경기는 8배 빠르게 시뮬레이션하고 온라인은 실제 서버 시간으로 입력만 보냅니다. 배포 사이트에는 이 패널을 표시하지 않습니다. 테스트 운전자도 동일한 주행·충돌·랩 규칙을 사용하며 서버에 결과를 직접 제출하지 않습니다.

물리 테스트와 브라우저 확인은 실제 휴대전화에서 손가락으로 조작한 검사와 다릅니다. 별도의 실기기 멀티터치·다양한 GPU 성능 검사는 필요합니다. `VERIFICATION.md`에 이번 실행에서 직접 확인한 항목과 배포 상태를 기록합니다.
